# Webhook Setup

Guide for setting up webhooks that deliver external data to the agent with proper DualView security labeling.

## Webhook Types

### Event-driven (push)

External services POST to the OpenClaw `/hooks/agent` endpoint when events occur.

Examples: GitHub webhooks, CI pipeline notifications, monitoring alerts.

### Time-based (polling)

A local script runs on a schedule (via the `cron` tool or systemd timer), fetches data from an external source, and POSTs it to the OpenClaw hooks endpoint.

Examples: checking an RSS feed every 10 minutes, polling a REST API for new items, checking email via IMAP.

## OpenClaw Hook Input Format

All webhook POSTs go to `/hooks/agent` with a bearer token. The payload has this structure:

```json
{
  "message": "<DualView webhook JSON goes here>",
  "channel": "telegram",
  "to": "8266736727",
  "name": "GitHub Issue Alert"
}
```

- `message` (required): the content delivered to the agent. For DualView, this should contain DualView webhook JSON (see below).
- `channel` (required): target platform (`"telegram"`, `"slack"`, `"discord"`, or `"last"` for the most recent channel).
- `to` (optional): recipient ID (chat ID, channel ID). If omitted, uses the default session.
- `name` (optional): display name for the hook source.

Authentication: `Authorization: Bearer <hooks.token>` header, where `hooks.token` is from `openclaw.json`.

## DualView Webhook Payload Format

The DualView webhook JSON (placed in the `message` field above) uses this format:

```json
{
  "data": {
    "field1": "value1",
    "field2": "value2"
  },
  "security": {
    "field1": "TRUSTED",
    "field2": "UNTRUSTED"
  },
  "template": "optional: {{field1}} said {{field2}}"
}
```

### Fields

**`data`** (required): the structured payload. Each key is a named field.

**`security`** (optional): per-field trust classification. Each key maps to `"TRUSTED"` or `"UNTRUSTED"`. Fields not listed default to `UNTRUSTED`. If omitted, all string fields are treated as UNTRUSTED.

**`template`** (optional): a Mustache-style string with `{{field}}` placeholders. When provided, the agent sees a rendered message instead of raw JSON. Trusted fields show their real values. Untrusted fields show symbols.

### Trust classification guidelines

Mark a field as `TRUSTED` when the value is generated by the infrastructure itself (not by an end user). Mark as `UNTRUSTED` when the value could contain user-supplied or attacker-controlled content.

Examples:

| Service | Trusted fields | Untrusted fields |
|---------|---------------|-----------------|
| GitHub issue | `number`, `author`, `labels`, `repo` | `title`, `body`, `comments` |
| Email | `from`, `date`, `message_id` | `subject`, `body` |
| CI pipeline | `pipeline_id`, `status`, `branch` | `commit_message` |
| Monitoring alert | `severity`, `host`, `timestamp` | `details`, `description` |

## Example: Polling webhook script

```typescript
// fetch-github-issues.ts
// Polls GitHub API for new issues and POSTs them to OpenClaw as DualView webhooks.
// Run: npx tsx fetch-github-issues.ts

import https from "https";
import http from "http";

// Configuration
const REPO = "owner/repo";
const GITHUB_TOKEN = "ghp_...";
const OPENCLAW_URL = "http://127.0.0.1:18789";
const HOOK_TOKEN = "dualview-bot-hook-token"; // from hooks.token in openclaw.json
const TARGET_CHANNEL = "telegram";
const TARGET_TO = "8266736727";

function get(url: string, headers: Record<string, string> = {}): Promise<string> {
  return new Promise((resolve, reject) => {
    https.get(url, { headers }, (res) => {
      let data = "";
      res.on("data", (c) => (data += c));
      res.on("end", () => resolve(data));
    }).on("error", reject);
  });
}

function post(url: string, body: string, headers: Record<string, string>): Promise<{ status: number; body: string }> {
  const u = new URL(url);
  return new Promise((resolve, reject) => {
    const req = http.request(u, { method: "POST", headers }, (res) => {
      let data = "";
      res.on("data", (c) => (data += c));
      res.on("end", () => resolve({ status: res.statusCode!, body: data }));
    });
    req.on("error", reject);
    req.write(body);
    req.end();
  });
}

// Fetch recent issues
const since = new Date(Date.now() - 10 * 60_000).toISOString();
const raw = await get(
  `https://api.github.com/repos/${REPO}/issues?since=${since}&state=open`,
  { Authorization: `Bearer ${GITHUB_TOKEN}`, "User-Agent": "dualview-webhook" },
);
const issues = JSON.parse(raw) as Array<{
  number: number;
  user: { login: string };
  labels: Array<{ name: string }>;
  title: string;
  body: string | null;
}>;

// POST each issue to OpenClaw
for (const issue of issues) {
  const dualviewPayload = JSON.stringify({
    data: {
      number: issue.number,
      author: issue.user.login,
      labels: issue.labels.map((l) => l.name),
      title: issue.title,
      body: issue.body ?? "",
    },
    security: {
      number: "TRUSTED",
      author: "TRUSTED",
      labels: "TRUSTED",
      title: "UNTRUSTED",
      body: "UNTRUSTED",
    },
    template: "New issue #{{number}} by {{author}}\nTitle: {{title}}\n\n{{body}}",
  });

  const res = await post(`${OPENCLAW_URL}/hooks/agent`, JSON.stringify({
    message: dualviewPayload,
    channel: TARGET_CHANNEL,
    to: TARGET_TO,
    name: "GitHub Issues",
  }), {
    "Content-Type": "application/json",
    Authorization: `Bearer ${HOOK_TOKEN}`,
  });

  console.log(`Issue #${issue.number}: ${res.status}`);
}
```

## When the external service cannot produce DualView format

Some services (GitHub native webhooks, Slack Events API, Telegram) send their own format. In these cases, use a transformer:

1. **Local transformer script**: receives the native webhook, converts to DualView format, and POSTs to OpenClaw
2. **Middleware/proxy**: sits between the external service and OpenClaw (future DualView feature)
3. **Polling instead of push**: write a script that calls the service's API and produces DualView format directly
